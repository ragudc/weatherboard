# Skill: Internationalization (i18n)

## Stack del proyecto
- Librería: `next-intl`
- Idioma por defecto: **English (`en`)**
- Segundo idioma opcional: **Spanish (`es`)**
- Estrategia de rutas: prefijo solo para locales no-default (`/es/...`)

## Estructura de archivos

```
weatherboard/
├── messages/
│   ├── en.json          ← textos en inglés (fuente de verdad)
│   └── es.json          ← textos en español (traducción)
├── src/
│   ├── i18n/
│   │   ├── routing.ts   ← define locales y defaultLocale
│   │   └── request.ts   ← configura next-intl por request
│   └── middleware.ts    ← manejo de rutas i18n
```

## Configuración de routing

```ts
// src/i18n/routing.ts
import { defineRouting } from "next-intl/routing"

export const routing = defineRouting({
  locales: ["en", "es"],
  defaultLocale: "en",
  localePrefix: "as-needed", // /en/... omitido, /es/... explícito
})
```

## Uso en componentes

### Server Components
```tsx
import { getTranslations } from "next-intl/server"

export default async function WeatherPage() {
  const t = await getTranslations("weather")

  return <p>{t("feelsLike")}: 72°F</p>
}
```

### Client Components
```tsx
"use client"

import { useTranslations } from "next-intl"

export const SearchBar = () => {
  const t = useTranslations("search")

  return (
    <Input
      placeholder={t("placeholder")}
      aria-label={t("label")}
    />
  )
}
```

### Metadatos SEO dinámicos
```tsx
// src/app/[locale]/layout.tsx
import { getTranslations } from "next-intl/server"
import { Metadata } from "next"

export async function generateMetadata(): Promise<Metadata> {
  const t = await getTranslations("meta")
  return {
    title: t("title"),
    description: t("description"),
  }
}
```

## Language switcher — patrón del proyecto

```tsx
"use client"

import { useLocale } from "next-intl"
import { useRouter, usePathname } from "next/navigation"

export const LanguageSwitcher = () => {
  const locale = useLocale()
  const router = useRouter()
  const pathname = usePathname()

  const toggleLocale = () => {
    const next = locale === "en" ? "es" : "en"
    // Reemplaza el prefijo de locale en la ruta actual
    const newPath = pathname.replace(`/${locale}`, next === "en" ? "" : `/${next}`)
    router.push(newPath || "/")
  }

  return (
    <button
      onClick={toggleLocale}
      aria-label="Switch language"
      className="text-sm font-medium text-muted-foreground hover:text-foreground transition-colors"
    >
      {locale === "en" ? "ES" : "EN"}
    </button>
  )
}
```

## Reglas obligatorias

| Regla | Detalle |
|---|---|
| Nunca hardcodees texto visible al usuario | Siempre usa `t("key")` |
| El inglés es la fuente de verdad | Agrega claves en `en.json` primero, luego en `es.json` |
| Namespaces por feature | `weather`, `forecast`, `search`, `aqi`, `units`, `common`, `meta` |
| Claves en camelCase | `feelsLike`, no `feels_like` ni `FeelsLike` |
| Nunca traduzcas en el API layer | Las respuestas de OpenWeatherMap se traducen solo en la UI |
| Fallback automático al inglés | Si falta una clave en `es.json`, `next-intl` usa `en.json` sin error |

## Checklist antes de hacer commit de un componente nuevo
- [ ] ¿Todos los textos visibles usan `t("key")`?
- [ ] ¿Las claves nuevas están en ambos archivos (`en.json` y `es.json`)?
- [ ] ¿Los `aria-label` y `placeholder` también usan `t()`?
- [ ] ¿Los metadatos SEO de la página usan `getTranslations("meta")`?
